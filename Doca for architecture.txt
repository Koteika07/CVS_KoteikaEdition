Подходы по хранению истории
    Дельты (Диффы / Patсhes): Храним первый файл целиком, а дальше - только изменения (diff).
        Минус: Чтобы получить версию N, нужно прочитать базу и применить N диффов. Это O(N)O(N)
        O(N) по времени. При удалении старого коммита ломается вся цепочка
    Полные снапшоты (Snapshots): Каждый коммит - полная копия всех файлов.
        Минус: Если проект на 1 ГБ и меняем одну строчку, коммит весит 1 ГБ. O(N)O(N)
        O(N) по месту на диске
    Адресуемое по содержимому хранилище (Content-Addressable Filesystem)
        Это гибрид. Храним снапшоты (дерево файлов), но используем криптографическое хэширование для дедупликации
        Суть: Если файл не изменился, его хэш (SHA-256) остается прежним. Новый коммит не копирует файл, а просто ставит ссылку на старый хэш
        Плюсы: Мгновенный checkout (мы просто читаем снапшот), экономия места (дедупликация),
        гарантия целостности (если байт изменится, хэш совпадать не будет)

Терминология
Объекты хранилища
Вся база данных СКВ состоит из трех типов объектов. Они хранятся в сыром виде (сжатые zlib) и идентифицируются только своим SHA-256 хэшем

    Blob (Бинарный большой объект): Содержит только содержимое файла. У него нет имени, нет путей, нет прав доступа - просто массив байтов
    Tree (Дерево): Аналог директории (папки). Содержит список записей: {"имя_файла": ("тип", "хэш")}. Типом может быть blob (файл) или tree (вложенная папка)
    Commit (Коммит):
        Ссылку на корневой Tree (снапшот файловой системы)
        Ссылку на родительский Commit (для связности истории)
        Сообщение, автора, время

Рабочие зоны 
    Working Directory (Рабочая директория): То, что вы видите в проводнике. Обычные файлы, которые вы редактируете.
    Index / Staging Area (Индекс / Область подготовки): Промежуточное состояние. "Черновик" следующего коммита. 
        Когда вы делаете add, вы копируете хэш файла из Рабочей директории в Индекс. Когда делаете commit, Индекс превращается в Tree.
    Object Store (Хранилище объектов): "Вечное" хранилище (наша папка .mycvs/objects). Сюда попадают данные, чтобы остаться там навсегда (пока не сработает сборщик мусора).

Указатели (The Pointers)

    Ref (Reference / Ссылка): Текстовый файл, содержащий 64-символьный хэш коммита. Ветки (heads) и Теги (tags) — это просто Refs.
    HEAD: Специальный Ref, указывающий на то, где вы сейчас находитесь. Обычно он содержит текст ref: refs/heads/main. 
        Если HEAD указывает напрямую на хэш коммита, это называется Detached HEAD (отсоединенный HEAD).

Используем Layered Architecture (Слоистую архитектуру). Каждый слой зависит только от того, что находится ниже него.
