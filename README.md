# CVS System - Koteika Edition

Собственная система контроля версий, реализованная на Python с нуля. Проект использует архитектуру **Content-Addressable Storage** (аналогично Git), где данные хранятся в виде криптографически хэшированных снапшотов с автоматической дедупликацией.

Код разделен на строгие слои (Infrastructure, Domain, Presentation) для обеспечения масштабируемости, чистоты архитектуры и легкого покрытия тестами.

## Возможности

- **Инициализация репозитория:** создание скрытой структуры `.KoteikaGit` для хранения метаданных и объектов
- **Управление индексом (Staging Area):** добавление файлов и целых директорий в область подготовки к коммиту
- **Создание коммитов:** фиксация снапшотов состояния с автоматическим связыванием с родительскими коммитами
- **Дедупликация данных:** идентичные файлы в разных коммитах хранятся на диске только один раз (благодаря SHA-256)
- **Управление ветками и тегами:** мгновенное создание указателей (refs) на конкретные коммиты
- **Переключение версий (Checkout):** безопасное восстановление рабочей директории из любого коммита, ветки или тега
- **Просмотр истории (Log):** вывод дерева коммитов с метаданными и списками файлов в каждом снапшоте
- **Целостность данных:** использование заголовков объектов и хэшей гарантирует защиту от скрытого повреждения данных

## Использование

Система управляется через командную строку. Запуск осуществляется через модуль:

```bash
python -m cvs <команда>
```

### Базовый сценарий работы

```bash
# 1. Инициализация нового репозитория
python -m cvs init

# 2. Создание тестовых файлов
echo "Hello Koteika" > readme.txt
mkdir src
echo "print('Hello')" > src/main.py

# 3. Добавление в индекс (Staging Area) и первый коммит
python -m cvs add readme.txt src
python -m cvs commit -m "Initial commit"

# 4. Изменение файла, добавление и второй коммит
echo "Hello Koteika Edition!" > readme.txt
python -m cvs add readme.txt
python -m cvs commit -m "Update readme"

# 5. Создание ветки и переключение на неё
python -m cvs branch feature-1
python -m cvs checkout feature-1

# 6. Добавление файла в ветке
echo "New feature code" > feature.txt
python -m cvs add feature.txt
python -m cvs commit -m "Add feature file"

# 7. Просмотр лога (истории коммитов)
python -m cvs log

# 8. Возврат в main и создание тега
python -m cvs checkout main
python -m cvs tag v1.0

# 9. Переключение по тегу (файл feature.txt исчезнет из рабочей директории)
python -m cvs checkout v1.0
```

### Доступные команды CLI

| Команда | Описание |
|---------|----------|
| `python -m cvs init` | Инициализировать новый репозиторий в текущей директории |
| `python -m cvs add <путь>` | Добавить файлы или директории в индекс (staging area) |
| `python -m cvs commit -m "msg"` | Зафиксировать текущее состояние индекса в новый коммит |
| `python -m cvs checkout <target>` | Переключиться на ветку, тег или конкретный SHA коммита |
| `python -m cvs log` | Вывести историю коммитов от текущего HEAD |
| `python -m cvs branch <name>` | Создать новую ветку, указывающую на текущий коммит |
| `python -m cvs tag <name>` | Создать неизменяемый тег на текущий коммит |

## Архитектура проекта

Проект построен по принципу **Layered Architecture** (Слоистая архитектура), что разделяет ответственность модулей:

1. **Infrastructure Layer** (`config.py`, `storage.py`) — отвечает за низкоуровневую работу с файловой системой, сжатие (`zlib`) и хэширование (`SHA-256`).
2. **Domain Layer** (`object.py`, `index.py`, `repo.py`) — содержит модели данных (`Tree`, `Commit`), управление Staging Area (`Index`) и оркестрацию высокоуровневых операций (`Repository`)
3. **Presentation Layer** (`cli.py`) — парсинг аргументов командной строки через `argparse` и маршрутизация вызовов к `Repository`

## Принцип работы

### Content-Addressable Storage

Вместо хранения файлов по именам, система использует **криптографические хэши** (SHA-256) как уникальные идентификаторы содержимого:

1. При добавлении файла вычисляется его SHA-256 хэш
2. Файл сохраняется в хранилище под именем, равным его хэшу
3. Если файл не изменился — его хэш остаётся тем же, и новая копия не создаётся
4. Это обеспечивает автоматическую дедупликацию и целостность данных

### Объекты хранилища

Система работает с тремя типами объектов:

- **Blob** — содержимое файла (бинарные данные)
- **Tree** — структура директории (список файлов и поддиректорий с их хэшами)
- **Commit** — снимок состояния (ссылка на корневой Tree, родительский коммит, сообщение, автор, время)

### Staging Area (Индекс)

Индекс — это промежуточная область между рабочей директорией и коммитом:

1. `cvs add` копирует файлы из рабочей директории в Object Store и записывает их хэши в индекс
2. `cvs commit` создаёт Tree из индекса и фиксирует его в новом коммите
3. Это позволяет коммитить изменения выборочно, а не все сразу=
